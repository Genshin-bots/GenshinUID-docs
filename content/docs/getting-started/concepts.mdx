## 一句话版本

| 名字 | 你可以把它想成… |
|------|----------------|
| **Core（早柚核心）** | **大脑**：算命令、跑插件、记数据库、可选 AI |
| **Bot** | **嘴巴和耳朵**：真正连 QQ / Telegram 等平台 |
| **适配器（Adapter）** | **翻译官**：把平台协议 ⇄ 早柚协议互转 |
| **插件（Plugin）** | **技能卡**：查 UID、画图、订阅推送等具体功能 |

<BeginnerTip title="最重要的一句话">

**Core 不是一个完整的聊天机器人。**  
它必须和上游 Bot（+ 适配器）一起用。只启动 Core、不连 Bot，群里永远收不到消息——这不是故障，是架构设计。

</BeginnerTip>

## 为什么要拆成「Core + Bot」？

<BeginnerTip variant="why" title="设计动机（可选阅读）">

- **一次编写，多端复用**：同一套插件逻辑可以接到 QQ、频道、TG…（取决于 Bot 支持的平台）。  
- **职责清晰**：平台协议天天变，改适配器即可，业务插件相对稳定。  
- **可远程部署**：Bot 在 A 机器、Core 在 B 机器（甚至公网 VPS）都行，用 `WS_TOKEN` 保护连接。

</BeginnerTip>

## 配置和数据会落在哪？

第一次成功启动 Core 后，仓库根目录会出现 **`data/`**（很重要，备份就靠它）：

| 路径 | 新手需要知道的 |
|------|----------------|
| `data/config.json` | 主人账号、端口、WS 令牌、WebConsole 注册码 |
| `data/core_config.json` | 自动更新、代理、镜像源等行为开关 |
| `data/plugins_configs/` | 每个插件一份配置 |
| `data/GsData.db` | 默认 SQLite 数据库（账号绑定等） |
| `data/ai_core/` | AI 相关（默认关着，可不管） |
| `gsuid_core/plugins/` | **业务插件源码**目录（不是 data 里） |

<BeginnerTip variant="remember" title="两个目录别搞混">

- **`data/`** = 运行产生的「存档」  
- **`gsuid_core/plugins/`** = 你装的「游戏 / 功能插件」代码  

Docker 用户必须把这两处挂到宿主机，否则容器一重建数据全没。

</BeginnerTip>

## 常见误解速查

| 误解 | 正解 |
|------|------|
| 「装了 Core 就能回消息」 | 还要装 **适配器 + Bot**，并 **装业务插件** |
| 「WebConsole 就是 Bot」 | WebConsole 是 **管理后台**，不是聊天入口 |
| 「AI 必须开」 | AI **默认关**；查 UID 等业务不依赖 AI |
| 「配置改了立刻全生效」 | 端口 / HOST / 多数核心项需要 **重启 Core** |

## 看完自测（心里过一遍）

1. Core 和 Bot 谁连谁？（答：Bot 当客户端连 Core）

3. 公网部署最少要改什么？（答：`HOST=0.0.0.0` + `WS_TOKEN`）
