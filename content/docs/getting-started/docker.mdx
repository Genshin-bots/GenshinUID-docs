<BeginnerTip title="Docker 是什么（10 秒）">

Docker 把「系统 + Python + 依赖 + Core」打成容器。  
你只要挂上「数据盘」和「插件盘」，升级镜像时存档还在。

</BeginnerTip>

<div data-pkg="mount">

**适合**：想跟仓库更新、偶尔改配置文件、开发插件。

```shell
git clone https://cnb.cool/gscore-mirror/gsuid_core.git
# 或 GitHub：https://github.com/Genshin-bots/gsuid_core.git
cd gsuid_core
cp .env.example .env
docker compose up -d --build
```

第一次构建会久一点。用 `docker compose logs -f` 看进度。

</div>

<div data-pkg="bundle">

**适合**：生产 / 「我只想跑起来」。

```shell
# 准备 docker-compose.bundle.yml 与 .env（设置 DATA_PATH、PLUGIN_PATH）
docker compose -f docker-compose.bundle.yml up -d
```

或 `docker run` 示例：

```shell
docker run -d \
  --name gsuid_core \
  --restart always \
  -p 8765:8765 \
  -v /opt/gscore_data:/gsuid_core/data \
  -v /opt/gscore_plugins:/gsuid_core/gsuid_core/plugins \
  -v gsuid_core_venv:/venv \
  docker.cnb.cool/gscore-mirror/gsuid_core:latest
```

Windows 路径请换成你的盘符目录，如 `D:/gscore/data`。

</div>

## 步骤 2：确认三个持久化挂载

<CheckItem
  step={2}
  title="数据盘 / 插件盘 / venv 都挂了吗？"
  badge={{ text: "必做", type: "danger" }}
  storageKey="gs-dk-persist"
>

| 容器内路径 | 存什么 | 不挂会怎样 |
|------------|--------|------------|
| `/gsuid_core/data` | 配置、数据库、日志、AI | **存档全丢** |
| `/gsuid_core/gsuid_core/plugins` | 业务插件 | 插件全丢 |
| `/venv` | Python 环境（命名卷） | 每次重建重装依赖 |

<Callout type="error" title="">

只 `-p 8765:8765` 而不挂 `data`，等于每次重建都是新号——血的教训。

</Callout>

</CheckItem>

## .env 新手常用项

```properties
PORT=8765
# 国内装依赖慢时换 PyPI 镜像，例如：
# GSCORE_PYTHON_INDEX=https://mirrors.aliyun.com/pypi/simple/

# 可选代理（宿主机代理端口按你的为准）
# GSCORE_HTTP_PROXY=http://host.docker.internal:7890
# GSCORE_HTTPS_PROXY=http://host.docker.internal:7890
```

## 和 Bot 互通时注意

| 拓扑 | Bot 里 host 怎么填 |
|------|-------------------|
| Bot 在宿主机，Core 在容器 | 通常 `127.0.0.1`（端口已映射） |
| Bot 也在容器 | 用 compose 服务名，或 `host.docker.internal` |
| Core 在远程 VPS | VPS 公网 IP + 安全组放行 + `WS_TOKEN` |

镜像通常已 `--host 0.0.0.0`。公网务必配 Token，见 [首次配置](./first-config/)。

## 升级与重置

```shell
# 拉新镜像（bundle）
docker compose -f docker-compose.bundle.yml pull
docker compose -f docker-compose.bundle.yml up -d

# 依赖坏了：删 venv 卷重建（data 还在）
docker compose down -v
docker compose up -d --build
```

## 常见错误

| 现象 | 处理 |
|------|------|
| `port is already allocated` | 改 `.env` 的 `PORT` 或关掉占用进程 |
| 容器秒退 | `docker logs` 看完整错误 |
| 权限写不了 data | 检查宿主机目录权限 |
| git 装插件卡死 | 容器内配 git 代理或 WebConsole 换镜像源 |
