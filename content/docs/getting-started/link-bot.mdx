## 总览：谁连谁？

```
QQ 等平台 ←→ 你的 Bot 程序（含适配器）──WebSocket 客户端──→ GsCore
```

- Core **不会**主动去连 QQ  
- 是 **Bot 主动连 Core**（像手机连 Wi‑Fi）

## 连接 URL 公式

```text
ws://{HOST}:{PORT}/{BOT_ID}?token={WS_TOKEN}
```

| 零件 | 填什么 | 例子 |
|------|--------|------|
| `HOST` | Core 的地址 | 同机 `127.0.0.1`；跨机为服务器 IP |
| `PORT` | Core 端口 | `8765` |
| `BOT_ID` | 你自定义的名字 | `NoneBot2` / `nb2` |
| `token` | 与 `config.json` 的 `WS_TOKEN` **完全一致** | 空 Token 时可省略部分适配器字段 |

## 多 Bot 共用一个 Core

每个 Bot 使用**不同的 `BOT_ID`**，共享同一个 `WS_TOKEN`：

```text
BotA → ws://IP:8765/bot_a?token=secret
BotB → ws://IP:8765/bot_b?token=secret
```

## 连不上？对照表

| 现象 | 原因与处理 |
|------|------------|
| Bot 报连接失败 | Core 没开 / IP 端口错 / 防火墙 |
| `1008 Policy Violation` | **Token 不一致** 或 Core 拒绝空 Token 的外网连接 |
| 能连上但没反应 | `masters` 未填导致部分命令无权限；或没装插件；或 `command_start` 前缀不匹配 |
| Docker 主机名解析失败 | 补 `extra_hosts: host.docker.internal:host-gateway` |
| 频繁断线 | 反代 `proxy_read_timeout` 太短；或网络不稳 |
