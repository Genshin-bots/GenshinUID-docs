## 配置 GsCore<Badge type="warning" text="普通" />

<Callout type="info" title="">

GsCore 有两个配置文件：

- `gsuid_core/data/config.json` ← 本节关注
- `gsuid_core/data/core_config.json` ← 通过 [网页控制台](./web-console) 调整，或参考 [GsCore 选项](../../advance/core-config)

首次启动 Core 后会自动生成这两个文件。

新版本开始，插件配置不再放在 `config.json` 的 `"plugins"` key 下，而是拆到 `data/plugins_configs/<name>.json` 里——首次启动时会自动从旧版迁移，无需手动操作。

</Callout>

<Callout type="error" title="">

如果 GsCore 和连接端不在同一台机器上，**强烈建议**配置 `WS_TOKEN` 或 `TRUSTED_IPS`，见 [配置 WsToken（跨机部署安全）](#配置-wstoken跨机部署安全)。

</Callout>

下面两种方式**二选一**——它们达成同一件事，不是「先 1 再 2」：

<div data-pkg="console">

<Callout type="tip" title="">

本节的核心目标就一句话：**把自己常用的账号加进主人账号列表**，让 Bot 知道「这是管理员」。

</Callout>

1. **启动 GsCore**（参考上一节）
2. **打开网页控制台**：浏览器访问 `http://localhost:8765/app`
3. **注册管理员**：首次进入需要注册，注册码在 `data/config.json` 的 `REGISTER_CODE` 字段，每人不同
4. **添加主人账号**：左侧【Core 配置】→ 主人账号列表 → 输入自己的 QQ 号（或其他平台账号）→ 回车 → 「确认修改」
5. **重启 GsCore**：控制台里的修改不会自动生效，发 `core重启` 命令或在控制台点重启
6. **验证权限**：发一条消息，后端日志里看到 `pm=0` 就说明配置成功

<details>
<summary>权限字段说明（点开看完整说明）</summary>

- `masters` = 主人账号列表（`pm=0`，最高权限）
- `superusers` = 超级用户账号列表（`pm=1`）

常见 `pm` 等级：`0=主人` / `1=超级用户` / `2=群主` / `3=群管理员` / `6=普通用户`，数字越小权限越高。

部分网页控制台版本会把 `masters` 显示为"管理员列表"——这里的"管理员"指主人账号，不是群管理员（`pm=3`）。

如果不确定账号怎么填，先用该平台给 Bot 发一条消息，从 GsCore 后端日志里复制你的 `user_id` 即可。

</details>

</div>

<div data-pkg="file">

<Callout type="tip" title="">

萌新只需要改 `masters` 字段——把 `["444835641"]` 里的数字换成你自己的账号。其它字段**可以完全不动**。记得数字/字符串加双引号。

</Callout>

```json
{
  "HOST": "localhost",
  "PORT": "8765",
  "masters": ["444835641"],
  "superusers": [],
  "misfire_grace_time": 90,
  "WS_TOKEN": "",
  "TRUSTED_IPS": ["127.0.0.1"],
  "REGISTER_CODE": "4e8cd750c93de5c5",
  "log": { "level": "INFO" },
  "command_start": [],
  "sv": {
    "Core管理": {
      "priority": 5,
      "enabled": true,
      "pm": 0,
      "black_list": [],
      "area": "ALL",
      "white_list": []
    }
  }
}
```

<details>
<summary>字段含义（点开看完整说明）</summary>

| 字段 | 含义 |
| --- | --- |
| `HOST` | 本机 Host，一般无需修改 |
| `PORT` | GsCore 运行端口，一般无需修改 |
| `masters` | 主人账号列表（`pm=0`），类型 `List[string]` |
| `superusers` | 超级用户账号列表（`pm=1`），类型 `List[string]` |
| `misfire_grace_time` | 定时任务超时时间，一般无需修改 |
| `WS_TOKEN` | 连接 WS 的 Token；不修改则只允许本机 Bot 连接 |
| `TRUSTED_IPS` | 信任的 IP 列表，类型 `List[string]` |
| `REGISTER_CODE` | 网页控制台注册码，每个人不同 |
| `log.level` | 日志等级，一般 `INFO` 即可；反馈 Bug 时改 `DEBUG` |
| `command_start` | 命令头，类型 `List[string]`；默认 `[]`；填入后所有命令必须带命令头 |
| `sv` | 插件注册的全部服务列表，均可通过网页控制台修改 |

</details>

</div>

</PkgManager>

## 配置 WsToken（跨机部署安全）<Badge type="warning" text="可选" />

<Callout type="warn" title="">

只有当 **GsCore 和 Bot 端不在同一台机器** 时才需要这一步：

- 同机部署（包括 Bot 和 Core 同时在 Docker 容器内）→ 不需要
- 跨机部署 → 必须配置 `WS_TOKEN` 或 `TRUSTED_IPS`

</Callout>

<Callout type="info" title="">

**Bot 端的 Token 必须和 GsCore 端的 `WS_TOKEN` 完全一致**。

</Callout>

<CheckItem
  step={1}
  title="在 GsCore 端配置"
  subtitle="任选其一即可"
>

两种方式等价，选你觉得方便的：

- **网页控制台**：打开 [网页控制台](./web-console) → 修改 `WS_TOKEN` 或 `TRUSTED_IPS`
- **改配置文件**：编辑 `data/config.json` 的 `WS_TOKEN` 或 `TRUSTED_IPS` 字段

</CheckItem>
