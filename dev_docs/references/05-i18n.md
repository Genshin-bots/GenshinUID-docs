# 五、i18n 多语言

> **返回主入口**：[`../SKILL.md`](../SKILL.md) · **上一章**：[四、怎么写文档](./04-writing-mdx.md) · **下一章**：[六、搜索](./06-search.md)

站点支持 **简体中文（zh-CN，默认）/ English（en）/ 日本語（ja）**。本章讲多语言的各个面在哪配、
如何加 / 改翻译、如何新增一门语言。

## 5.1 语言定义

`lib/i18n.ts` 是唯一的语言清单：

```ts
export const i18n = defineI18n({
  defaultLanguage: 'zh-CN',
  languages: ['zh-CN', 'en', 'ja'],
})
```

URL 形如 `/<lang>/docs/...`；根路径 `/` 会 redirect 到 `/zh-CN/`（`app/page.tsx`）。

## 5.2 多语言涉及的「五个面」

| 面 | 文件 | 说明 |
|----|------|------|
| 1. 文档正文 | `content/docs/**/*.mdx` | 用 `<name>.<lang>.mdx` 提供译文（见 §5.3） |
| 2. UI 文案 | `lib/layout.shared.ts`（`i18nUI`） | 搜索 / TOC / 上一页等界面字串三语 |
| 3. 顶栏菜单 | `lib/nav-config.ts` | 下拉菜单、版本、语言切换项，按 `lang` 分支 |
| 4. 首页文案 | `lib/home-content.ts` | Hero / 特性卡片 / 团队 / 贡献者标题，按 `lang` 分支 |
| 5. 侧边栏分组名 | `content/docs/**/meta.json` | 分组 `title` / 顺序（目前主要中文） |

> 改一处文案别忘了它属于上面哪个"面"。最常被漏的是 **UI 文案（面 2）** 和 **首页（面 4）**。
>
> **首页贡献者区**：贡献者数据从 GitHub `/contributors` 接口拉取（`per_page=100`），由
> `components/Contributors.tsx` 渲染成**保留原 VitePress 风的「重叠圆形」堆叠样式**——
> 一行 24 个，多出的自动换到下一行继续堆叠，**展示全部**贡献者（不再 +N 折叠）。
> 文案 `contributorsTitle` / `contributorsLabel` / `contributorsViewAll` 仍在
> `lib/home-content.ts` 配。

## 5.3 文档译文约定

- 默认语言（zh-CN）：`foo.mdx`
- 英文：`foo.en.mdx`；日文：`foo.ja.mdx`
- **缺失译文会回退到默认语言**（zh-CN）。所以目前绝大多数文档只有 zh-CN 版，
  访问 `/en/docs/...` 会显示中文内容——这是有意的渐进式翻译，不是 bug。
- 只有 `content/docs/index.*` 提供了完整三语首页文档。

## 5.4 侧边栏顺序 / 分组：`meta.json`

每个目录可放一个 `meta.json` 控制该层的标题、图标与页面顺序：

```json
{ "title": "快速开始", "icon": "Rocket", "pages": ["install-core", "docker-core", "web-console", "..."] }
```

- `pages` 数组里既可以是文件名（页面），也可以是子目录名（子分组）。
- 根 `content/docs/meta.json` 决定**顶层分组的顺序**。
- `icon` 是 lucide 图标名（由 `source.ts` 的 `lucideIconsPlugin` 解析）。

## 5.5 顶栏导航与首页文案

- `lib/nav-config.ts`：`getNavItems(lang)` / `getVersionNavItems(version, lang)` /
  `getLanguageOptions()`，全部 `if (lang === 'en') … if (lang === 'ja') … 默认 zh-CN`。
  里面的站内链接**要带 `/<lang>/docs/...` 全前缀**且结尾 `/`。
  - 例外：**实时聊天室入口直接链 `/<lang>/chat/`**（独立全页路由，不在 `/docs` 网格里）。
  - 历史 `/<lang>/docs/sp/chat/` 仍保留作为兼容，但 `nav-config` 不再指向它，
    旧链接由 `content/docs/sp/chat.mdx` 的说明文字引导到 `/chat/`。
    详见 [十、实时聊天室路由](./10-chat-route.md)。
- `lib/nav-config.ts` 的 `NavItem` / `NavSubItem` 还带 `icon: string` 字段，是
  lucide-react 命名导出名（不是 emoji）——`components/DocsNav.tsx` 的 `getIcon` 据此
  渲染彩色 icon。**新加 / 改 icon 名称时必须先经**
  `node -e "const {icons} = require('lucide-react'); console.log('<NAME>' in icons)"`
  **验证为 `true`**，否则会静默不渲染（见 [七、坑 #19](./07-pitfalls.md)）。
  颜色由 CSS 变量 `--nav-accent` 控制，主按钮用 `.nav-trigger--quickstart` /
  `--plugins` / `--version` 三个 className 显式分色（详见
  [二、§2.7.4](./02-theme-and-styling.md)）。
- `lib/home-content.ts`：`getHomeContent(lang)` 返回 Hero / features / team。
  其中 feature/action 的 `link` 写成 `/docs/...`（首页组件会自动加 `/<lang>` 前缀），
  **务必带 `/docs`**，否则跳到 `/<lang>/started/...` 会 404。见 [七、坑 #3](./07-pitfalls.md)。

## 5.6 新增一门语言（例如 ko）

1. `lib/i18n.ts`：`languages: ['zh-CN','en','ja','ko']`。
2. `lib/layout.shared.ts`：在 `i18nUI` 的第二参里加 `ko: { search:…, toc:…, … }` 全套 UI 文案。
3. `lib/nav-config.ts`：在三个函数里加 `if (lang === 'ko')` 分支。
4. `lib/home-content.ts`：加 `ko` 的 `getHomeContent` 分支。
5. `components/SearchDialog.tsx` + `app/api/search/route.ts`：若该语言是 CJK，配对应分词器
   （见 [六、搜索](./06-search.md)）；拉丁语言用 `'english'` 即可。
6. 文档译文按需补 `*.ko.mdx`（缺失自动回退 zh-CN）。
7. `pnpm build` 验证 `generateStaticParams` 为新语言生成了页面。
